# Building Relight

## Prerequisites
- Unity Hub with **Unity 6000.1.9f1** editor.
- Android Build Support (SDK/NDK/OpenJDK) for APK builds.
- iOS Build Support and macOS/Xcode for iOS builds.
- Unity Test Framework via Package Manager.

## First editor run
1. Clone the repository and open its root as a Unity project.
2. Wait for packages to import and inspect the Console for errors.
3. Select **Relight > Initialize Playable Scene**.
4. Open **Assets/Scenes/Relight.unity** and press Play.
5. Test building/removing structures, restoration, upgrades, and restart persistence.
6. Open **Window > General > Test Runner** and run all **13** EditMode tests.
7. Verify the large planet preview, highlighted starter mission, different planet palettes, region-completion feedback, and the two-tap REPAIR action.
8. Test a fresh install: place POWER next to LIFE, add another MINE, and complete the first region.
9. Test corrupted primary-save recovery, restart persistence, and actual offline production on a device.

The first-run scene is intentionally generated by an Editor menu command and is not yet checked in. Commit it only after successful local Unity verification. The game UI is instantiated by RelightGame at runtime.

## Android development build
- Install Android Build Support, switch to Android in Build Profiles if required.
- Select **Relight > Build Android Development APK**.
- Check the Console/build report. Output, if successful: `Builds/Relight-dev.apk` (ignored by Git).
- Install and verify on a physical Android phone.
- This is **not** a signed production Android App Bundle.

## iOS
No iOS build automation is included yet. Requires macOS, Xcode, Apple Developer signing, provisioning, TestFlight and real-device validation.

## Automated verification (source-level only)

GitHub Actions [Core verification](../../actions/workflows/core-verification.yml) runs after commits to feature branches. It compiles and exercises the actual Unity-independent world model with .NET 8, parses all Unity C# files using Roslyn, and validates JSON configuration. This is meaningful regression evidence, **not** a Unity compilation or mobile build. Check the latest workflow run and logs before citing a passing status.

## Production blockers
- No Unity editor compilation or device run has yet been performed by the assistant. Static source checks (balanced braces/parentheses and parseable JSON) are not substitutes for compilation.
- UI still uses placeholder panels and icons; the planet is generated procedurally and has not been visually reviewed on a real device.
- No sound, accessibility pass, tutorial, analytics, ads or purchases.
- No signing, package IDs, privacy policy, consent flow or store metadata.
- Unity/editor compatibility and current Android/iOS SDK requirements must be checked at release time.
- Build CI requires appropriate Unity licensing and platform credentials.

## Review policy
A source commit is not proof of a working build. Record editor version, platform, build logs, test results and screenshots before approving a baseline.
